## Цель работы

Перевести доску заявок с хранилища одного браузера на сервер, чтобы одни
и те же заявки видели все открытые окна, и подключить ИИ-диспетчера, который
определяет категорию заявки и присылает мастеру сообщение с кнопкой «Взять».

## Чем работала

Node.js 26 LTS, npm 11, Vite 8, React 19, TypeScript 7, Oxlint, VS Code,
Docker Desktop 29.9.3, PocketBase 0.40.6, библиотека `pocketbase@0.28.1`,
n8n 2.45.4, Ollama 0.40.12 с моделью qwen2.5:3b, Telegram Bot API.

## Ход работы

**2.1 — эффекты.** Добавила в `App` три эффекта: `document.title` с числом
новых заявок, таймер на 5 секунд для сообщения над списком и подписку на
`keydown` окна для сброса фильтра по Esc. Проверила опыты с журналом в
консоли: без массива зависимостей эффект бегает после каждой отрисовки,
с пустым `[]` заголовок застывает; StrictMode в разработке запускает эффекты
дважды. У таймера и подписки обязательно возвращаю функцию очистки — иначе
старый таймер стирает новое сообщение, а Esc срабатывает дважды.

**2.2 — PocketBase.** Собрала образ по своему `Dockerfile` (Alpine + архив
PocketBase 0.40.6), добавила службу и том `pb_data` в `compose.yaml`, создала
суперпользователя командой внутри контейнера. В панели `localhost:8090/_/`
завела коллекцию `requests`: поля повторяют тип `RequestItem`, обязательные
отмечены Required, у `category` и `status` — Select со списками значений.
Настроила пять правил: чтение всем, создать только со статусом «Новая»,
изменить — только без полей title/room/details, удалить — только «Готово».
Заполнила коллекцию пятью заявками и проверила правила запросами в обход
формы: создание «Готово» даёт 400, правка названия — 404, смена только
статуса — 200.

**2.3 — загрузка данных.** Вынесла все запросы в `api.ts`: общая `callApi`
превращает в понятную ошибку и «сервер не отвечает», и отказ с кодом.
Убрала `storage.ts` и localStorage, поменяла `id` на строку, убрала
`initialRequests`. Список теперь грузит эффект с `let ignore`, `async load()`
и очисткой; добавила `loading`, `error`, `attempt` и кнопку «Повторить».
Добавление, смена статуса и удаление сначала отправляют POST/PATCH/DELETE,
и только после ответа меняют состояние — через функцию обновления
`setRequests((list) => …)`, чтобы не потерять чужие правки за время запроса.

**2.4 — собственный хук.** Перенесла всё, что относится к данным, в
`useRequests.ts`: четыре состояния, эффект загрузки, `retry`, `add`, `next`,
`remove`. `App.tsx` стал отвечать только за экран и тексты сообщений.
Проделала два опыта: вызов хука ещё и в шапке даёт два независимых списка
и четыре запроса вместо двух, а хук после `return` по условию ломает
страницу («Rendered fewer hooks than expected»), потому что React раздаёт
состояния по порядку вызовов. Линтер `rules-of-hooks` ловит это сразу.

**2.5 — обновление по событиям.** Поставила `pocketbase@0.28.1`, написала
`realtime.ts` с `subscribeRequests` и подписалась в хуке эффектом с пустым
массивом зависимостей. Без проверки моя же заявка появлялась дважды — ответом
на POST и событием `create`. Добавила чистую функцию `upsertRequest`:
заменить запись, если `id` уже есть, иначе поставить в начало. Теперь и ответ,
и событие дают одну карточку.

**П2 и А2.** Сверила работу с чек-листом проекта, подготовила три службы в
`compose.yaml` (n8n, PocketBase, Ollama), `.env.example` для токена, два
шаблона процессов n8n — «ИИ-диспетчер» на пять узлов и «Кнопка «Взять»»
на девять. В первом процессе модель получает промпт и JSON-схему ответа,
категория уходит PATCH-ем в базу, в Telegram приходит сообщение с inline-кнопкой.
Второй раз в 10 секунд забирает нажатия `getUpdates`, переводит заявку
в «В работе» и правит сообщение. Токен вынесен в `.env` и в `.gitignore`.

## С чем пришлось разобраться отдельно

- Эффект нужен для связи с внешним миром, но не для значений из состояния:
  `newCount` и `visible` я считаю при отрисовке.
- Флажок `ignore` отбрасывает ответ того запуска эффекта, который StrictMode
  уже очистил; иначе два запроса дали бы два сохранения списка.
- `setLoading(false)` стоит после `try` и `catch`, а не внутри `try`: загрузка
  заканчивается и при успехе, и при ошибке.
- `attempt` в зависимостях эффекта не читается внутри — он нужен только чтобы
  «Повторить» запустило эффект заново.
- `upsertRequest` решает дубль: сервер присылает событие и окну, которое
  само отправило заявку.
- Секреты (токен бота, пароль суперпользователя) в коде не держу: токен в
  `.env`, пароль только в команде создания суперпользователя.

## Вывод

Доска перестала быть «одним браузером»: заявки лежат в PocketBase, окна
обмениваются изменениями по SSE, а код данных вынесен в хук. Проверки на
сервере дублируют проверки формы — запрос в обход формы всё равно не пройдёт.
Модель в автоматизации полезна как помощник: на шести проверочных заявках
категория верна в четырёх, поэтому правило Update разрешает мастеру
исправить категорию в панели, а доска покажет правку сразу.

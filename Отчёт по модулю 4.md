## Ход работы

**4.1 — тесты компонентов.** Поставила Vitest, jsdom и пять пакетов Testing Library, добавила `npm test`. Для `jsdom` настроила `vite.config.ts` и `setupTests.ts`. Тесты страницы показывают `SitesPage` в `MonitoringContext` с придуманными данными и `MemoryRouter` — ни сети, ни файлов. Два теста по требованиям нашли ошибки, которые при проверке руками не видны: «Все 3 сайтов открываются» вместо «Все 3 сайта» и «Не открываются: 3 из 3», когда проверок ещё не было. Добавила функцию `sitesWord` и переписала сводку. Тест щелчка по карточке, тест ошибки загрузки с подменённым `fetch` и восемь тестов склонения довели набор до 20; после главы 4.3 — до 23. Попутно проверила, что тест, ожидание которого списано с результата, ничего не ловит.

**4.2 — доступность.** Lighthouse поставил страницам 94 и 91 из-за контраста: зелёная строка статуса давала 3,44:1, синие ссылки на сером фоне — 4,36:1 при норме 4,5:1. Заменила цвета на `#1e7a46` и `#2563d0`. Опыт с карточкой на `div` показал границы автоматической проверки: мышью карточка работает, Lighthouse ставит 100, а Tab до неё не доходит. Поймали тесты по роли `link` и линтер с плагином `jsx-a11y`. Поставила `<h2>` с названием сайта первым внутри ссылки — так программа чтения называет карточку сначала по названию. Добавила `<title>` каждой странице (шаблонная строка для `SitePage`), `role="status"` у загрузки, `role="alert"` у ошибки, `<caption>` у таблицы истории. В `deploy.yml` перед сборкой теперь стоят `npm run lint -- --deny-warnings` и `npm test` — сайт с упавшим тестом не публикуется.

**4.3 — задача агенту.** Написала `AGENTS.md` с версиями, командами проверки и правилами кода. Задание содержало «Что сделать», «Правила проекта» и «Готово, когда». Агент сначала трижды ответил «изменения не нужны» (`git status` пустой), затем в пошаговом задании допустил пять ошибок: нет `import { useState }`, хук после `return`, поле поиска под карточками, лишний пробел в чужой строке, тесты без `setup()` и `await`. Возврат с готовыми правками за шесть минут не исправил ни одной. Правки отменила, поиск и флажок написала вручную, взяв из ответа агента `filter` и три сценария тестов. Всё записано в `monitoring/ai-log.md`.

**4.4 — Angular.** Создала `monitoring-ng` командой `ng new`. `types.ts`, `status.ts`, `plural.ts`, данные и стили перенесла копированием — в них нет обращений к React. Провайдер с `useEffect` и контекстом заменила служба `@Service()` с двумя `httpResource`: `value()`, `isLoading()` и `error()` уже внутри. Состояние страницы — `signal`, сводка и показанный список — `computed`, разметка — шаблон с `@if`/`@for`, `[routerLink]` и class bindings. Заголовки вкладок заданы `title` в маршрутах. Тест через `TestBed` с подменённой службой проверяет сводку, адрес ссылки, поиск и пустой результат. Сборка 258 КБ, 4 теста зелёные.

**П4 — дайджест новостей.** Собрала `digest` по трём заданиям из `tasks/`. `loadDigest` читает `{"news": [...]}`, превращает строку тегов «ИИ, наука» в массив и сортирует от свежих к старым; при ответе не ok выбрасывает «Дайджест не загрузился: код N.». Страница показывает карточки со ссылкой в новой вкладке, источником, датой, пересказом и метками; поиск по заголовку и пересказу, выбор тега и флажок «Только непрочитанные» работают вместе, список вычисляется при отрисовке. Отметка «прочитано» снимается повторным нажатием и хранится в `localStorage`. Пять тестов с подменённой сетью. Адрес веб-приложения задан `VITE_DIGEST_URL`, ключа и токена в коде нет.

**А4 — автоматизация.** Подготовила `apps-script/Code.gs`: `doGet` отдаёт новости из листа `news`, `doPost` дописывает только новые `id` и только с ключом `KEY` из свойств скрипта. Пометка `/** @OnlyCurrentDoc */` ограничивает доступ одной таблицей. Два процесса n8n: утренний читает три RSS-ленты, отбирает свежие, просит модель пересказать и поставить теги, проверяет ответ по списку тегов и пишет в таблицу; вечерний забирает новости за сутки и отправляет в Telegram одним сообщением с учётом лимита 4096 знаков. В `compose.yaml` добавлены `DIGEST_URL`, `DIGEST_KEY`, `TELEGRAM_CHAT_ID`.

## Проверка

```
monitoring:     npx tsc -b · lint --deny-warnings · CI=true npm test — 23 теста · npm run build
monitoring-ng:  CI=true npm test — 4 теста · ng build — 258 КБ
digest:         npx tsc -b · lint --deny-warnings · CI=true npm test — 5 тестов · npm run build
```

Все команды прошли без ошибок и предупреждений. Тесты, линтер и проверка типов стоят в конвейерах публикации `monitoring` и `digest`.

## С чем пришлось разобраться отдельно

- Тест должен падать хотя бы раз: иначе неизвестно, проверяет ли он требование. Опыт с заменой «мс» на «ms» это показал.
- Ожидание, списанное с результата, закрепляет ошибку и мешает её исправить.
- Lighthouse находит только автоматически проверяемое: контраст да, а карточку на `div` с `onClick` — нет. Tab и дерево доступности проверяю руками.
- Ни одна проверка по отдельности не находит все ошибки агента: `tsc` ловит импорт, линтер — порядок хуков, тесты — отсутствие роли, чтение diff — расположение поля и лишний пробел.
- Один удачный запуск агента ничего не доказывает: модель случайна, проверять нужно после каждого.
- В Angular данные загружает служба, а не провайдер; `httpResource` сам хранит загрузку и ошибку, поэтому кода меньше.
- Ключ записи Apps Script и токен бота не должны попадать ни в код, ни в `AGENTS.md`, ни в журнал: код публикуется, секреты — нет.

## Что осталось перед защитой

1. Создать таблицу и веб-приложение Apps Script, получить `/exec`, задать `KEY` — нужно сделать в моём Google-аккаунте.
2. Вписать адрес в `.env`, поднять n8n, вставить оба процесса и снять снимок сообщения бота.
3. Прогнать Lighthouse на `digest` и пройти страницу клавишей Tab; при находках завести новое задание агенту.
4. Залить код в репозитории `digest` и `monitoring-ng`, оформить `projects/p4-digest` в репозитории курса.

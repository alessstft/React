## Цель работы

С нуля собрать рабочее React-приложение «Доска заявок»: форма, список
карточек, статусы, фильтр, сохранение данных между перезагрузками, и
подключить к нему уведомление о новой заявке в Telegram через n8n.

## Чем работала

Node.js 26 LTS (26.13.1), npm 11, Vite 8, React 19, TypeScript 7, Oxlint, VS Code,
браузер, Docker Desktop, n8n 2.45.4, @BotFather. Все инструменты бесплатные,
как и требуется в дисциплине.

## Ход работы

**1.1 — рабочее место.** Установила Node.js 26 LTS с nodejs.org,
проверила `node -v` и `npm -v`. Первый `npm install` в уже открытом VS Code
не сработал — редактор пришлось закрыть и открыть заново, потому что терминал
читает PATH только при запуске; в PowerShell ещё разрешила сценарии
`RemoteSigned` для `npm.ps1`. Создала проект командой
`npm create vite@latest zayavki -- --template react-ts`, выбрала Oxlint,
поставила пакеты `npm install`, запустила `npm run dev`. Разобрала цепочку
`index.html → main.tsx → App.tsx` и проверила HMR на счётчике шаблона.
Убрала лишние файлы шаблона — `App.css` и `assets`.

**1.2 — JSX и компоненты.** Разделила страницу на `Header`, `RequestForm`
и `RequestCard`, каждый в своём файле в `src/components`. Собрала их в `App`
через фрагмент `<>…</>`, написала стили: тёмная шапка, две колонки через
`grid`, карточки, форма. Специально проверила ошибку с двумя корневыми
элементами и правила `className` / `htmlFor`.

**1.3 — props.** Описала тип `RequestCardProps`, распаковала props в
параметре функции, передала три разные заявки из `App`. Ограничила статус
объединением `'Новая' | 'В работе' | 'Готово'`, сделала его необязательным
со значением по умолчанию. Посмотрела, как `tsc -b` ловит забытое свойство
и опечатку в статусе, хотя страница в dev-режиме всё равно открывается.

**1.4 — состояние и события.** Сначала обработчик кнопки печатал в консоль,
потом я попробовала хранить статус в обычной переменной — страница не
менялась, линтер подсказал «Consider using state instead». Переписала на
`useState`, добавила кнопку «Взять в работу / Завершить». Затем подняла
состояние в `App`, чтобы шапка считала новые заявки: карточка получает
`status`, а о щелчке сообщает функцией `onNext`.

**1.5 — списки и условия.** Вынесла пять заявок в `requests.ts`, вывела
карточки через `map` с `key={r.id}`. Проделала оба опыта: без `key` ругается
консоль и линтер, а ключ-индекс после удаления заявки «передаёт» раскрытые
подробности соседней карточке — вернула `id`. Смену статуса и удаление
делаю только новым массивом через `map` / `filter` и `{ ...r }`.
Добавила раскрытие подробностей по кнопке и фильтр по статусу.

**1.6 — формы.** Подключила все четыре поля к состоянию (`value` +
`onChange`), сначала нарочно оставила `value` без `onChange` и убедилась,
что текст не набирается. Перехватила отправку через `onSubmit` и
`event.preventDefault()`, добавила заявку в начало списка, очистила форму.
Потом добавила проверку `trim()` на название и кабинет с сообщением под формой.

**1.7 — сохранение и отправка.** Убедилась, что после F5 заявка пропадает,
и вынесла чтение/запись в `storage.ts` (localStorage + JSON). Все изменения
пропустила через одну функцию `update`, чтобы и состояние, и хранилище
обновлялись вместе. В `notify.ts` написала `fetch` с `POST`, заголовком
`Content-Type: application/json` и `try … catch`: при выключенном n8n доска
не падает, а показывает честное сообщение.

**П1 и А1.** Сверила доску со всеми пунктами обязательных требований,
подготовила `compose.yaml` и шаблон процесса из двух узлов, расписала
настройку бота и публикацию вебхука. Вариант службы уточню у преподавателя —
переделка касается только данных и текстов, механизмы те же.

## Проверка

```
npm run build   → tsc -b и vite build: успешно, dist/ собран
npm run lint    → 0 ошибок, 0 предупреждений
```

В браузере проверила: пять заявок и «Новых заявок: 3»; пустая форма не
отправляется; заполненная заявка встаёт первой, форма очищается, счётчик
становится 4; кнопка меняет статус и счётчик; фильтр «Новая» оставляет
три карточки; после перезагрузки и новая заявка, и изменённый статус
остаются на месте; консоль без ошибок. При выключенном n8n вижу expected
сообщение «уведомление не отправлено: сервер автоматизации недоступен».

## С чем пришлось разобраться отдельно

- `key` беру из `id`, а не из индекса: после удаления элементы сдвигаются,
  и React отдаёт состояние «open» не той карточке.
- Массив из состояния меняю на месте нельзя — React сравнивает ссылку.
  Всегда строю новый массив.
- `useState(loadRequests)` без скобок: иначе хранилище читалось бы при
  каждой отрисовке.
- `event.preventDefault()` обязателен, иначе браузер перезагрузит страницу
  и всё состояние пропадёт.
- Сначала кладу заявку на доску, только потом отправляю уведомление:
  доска должна работать и без n8n.
- После установки Node.js `npm` не находился в старом терминале: VS Code
  считывает PATH при запуске, поэтому его надо перезапустить, а в PowerShell
  разрешить `RemoteSigned` — иначе не запускается `npm.ps1`.

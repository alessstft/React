## Цель работы

Разделить доску заявок на страницы с собственными адресами, убрать проброс
props через контекст и собрать второе приложение, которое можно опубликовать
на GitHub Pages без своего сервера. К нему добавить ночную проверку сайтов
по расписанию и оповещение в Telegram.

## Чем работала

Node.js 26 LTS, npm 11, Vite 8, React 19, TypeScript 7, Oxlint, VS Code,
`react-router@8.5.1`, PocketBase 0.40.6, Git, GitHub Actions, Node.js-скрипт,
Telegram Bot API.

## Ход работы

**3.1 — маршрутизация.** Поставила `react-router@8.5.1`, обернула приложение
в `BrowserRouter`. Вынесла доску в `pages/BoardPage.tsx`, добавила
`StatsPage`, `RequestPage` с параметром `/requests/:id` и `NotFoundPage`
для пути `*`. Меню в шапке сделала на `NavLink`: переход меняет адрес через
History API без перезагрузки, поэтому список заявок не запрашивается заново.
Проверила опыт с обычным `<a href>` — там страница грузится целиком и фильтр
сбрасывается. Заголовок карточки стал ссылкой `Link` на страницу заявки,
`useParams` достаёт номер из адреса, `useNavigate` возвращает на доску
после удаления.

**3.2 — контекст.** Собрала три части: `board.ts` с типом `Board`,
`BoardContext = createContext<Board | null>(null)` и хуком `useBoard`,
`BoardProvider.tsx` с `useRequests`, сообщением и обработчиками, и подключение
провайдера в `main.tsx`. Без провайдера хук падал с понятной ошибкой —
проверила этот опыт в консоли. Страницы и шапка стали читать данные сами,
`App.tsx` сократился до сообщения и четырёх маршрутов. В отличие от опыта
главы 2.4, список один на всё приложение: после смены статуса на странице
заявки счётчик в шапке и таблица статистики показывают одно и то же число.
Фильтр оставила в `BoardPage` — он нужен только доске.

**3.3 — сборка и публикация.** Создала отдельный проект `monitoring` рядом
с рабочей папкой. Он читает `public/data/sites.json`, поэтому не зависит от
PocketBase. Собрала `dist` командой `npm run build`, посмотрела собранные
файлы, проверила через `npm run preview`: открытый двойным щелчком
`index.html` не работает, нужен веб-сервер. Настроила `base: '/monitoring/'`
в `vite.config.ts` и путь `` `${import.meta.env.BASE_URL}data/sites.json` ``
в коде — без этого на Pages ссылки и запрос уходили в корень аккаунта
и давали 404. Написала `.github/workflows/deploy.yml`: checkout, Node.js 24,
`npm ci`, сборка, упаковка `dist`, публикация.

**3.4 — расписание.** Написала `scripts/check.mjs`: читает список сайтов,
запрашивает каждый с `AbortSignal.timeout(15000)`, пишет код ответа и время
в `results.json`, хранит 30 последних проверок. Добавила статусы в приложение.
Конвейер `check.yml` запускается по `cron: '0 21 * * *'` (00:00 по Москве)
и кнопкой `workflow_dispatch`, сохраняет результаты коммитом бота. Разобрала
две ошибки: без `permissions: contents: write` отправка падала с 403, а коммит
бота не запускал публикацию — поэтому добавила задание `publish` с
`needs: check` и `workflow_call` в `deploy.yml`, плюс `ref: main` в checkout.

**П3 — проект.** Собрала многостраничный монитор: маршруты `/`, `/site/:id`,
`/about`, `*`; контекст `MonitoringProvider` с загрузкой двух файлов;
функцию `statusText` вынесла в отдельный файл; на главной считаю сводку
«Не открываются: N из M»; на странице сайта показываю, сколько раз он
открывался, и таблицу истории с подсветкой неудачных проверок. Добавила
`basename` у `BrowserRouter` и шаг `cp dist/index.html dist/404.html`
в конвейере для прямых ссылок.

Список сайтов собрала из опубликованных на GitHub Pages работ нашей группы:
главная страница группы, этот монитор, проект PPTX → SCORM и «Дома
Санкт-Петербурга», плюс два справочника курса. Седьмой пункт «Проверка
оповещения» ведёт на бота https://t.me/FORREACT_bot: страница отвечает 200,
поэтому карточка зелёная и показывает «Работает · N мс». Чтобы получить
снимок сообщения бота, я временно подставляла неработающий адрес и обнуляла
историю проверок. У каждого сайта свой `id` латиницей. Когда однокурсники
пришлют адреса своих мониторов, заменю часть строк.

Ещё сделала три дополнительных задания из §4: долю удачных проверок
на карточке, кнопку «Только неработающие» и полосы времени ответа
в таблице истории.

**А3 — оповещение.** Добавила в скрипт функцию `notify`: токен и номер чата
читаю из `process.env`, значения приходят из секретов репозитория через
раздел `env` шага. Скрипт сравнивает новую проверку с `history[1]` и пишет
только об изменениях — «🔴 Не открывается» и «🟢 Снова работает». Если
изменений нет, сообщения нет. На трёх пробных запусках все семь адресов
ответили 200, поэтому сообщений не было — «Изменений нет, сообщение не
отправлено». Так и задумано: бот пишет только о переходах «работал ⇄ не работает».

В браузере с запущенным PocketBase прошла доску `/`, статистику `/stats`

и выделение активного пункта меню.
Консоль без ошибок React.

## С чем пришлось разобраться отдельно

- `<NavLink>` и `<a href>` дают одинаковый адрес, но по-разному: первый
  меняет только путь, второй перезагружает всё приложение.
- Состояние страницы живёт, пока страница на экране: при уходе на `/stats`
  `BoardPage` удаляется, и фильтр возвращается к «Все».
- Контекст доступен только внутри провайдера; `useBoard` проверяет `null`
  и сразу говорит, в чём проблема.
- `base` исправляет ссылки в `index.html`, но не строки внутри кода — для
  них нужен `import.meta.env.BASE_URL`.
- Имя репозитория должно совпадать с `base`: сначала репозиторий назывался
  `monitoring-`, и собранные ссылки вели в `/monitoring/`, отчего сайт был
  пустым. Переименовала репозиторий в `monitoring` — адрес и `base` совпали.
- Лишняя запятая в конце массива `sites.json` ломает весь JSON: приложение
  показывает сообщение об ошибке вместо карточек. Убрала её.
- Pages отдаёт только существующие файлы, поэтому для маршрутов нужна
  копия `index.html` под именем `404.html`.
- `cron` считается в UTC: 21:00 UTC — это 00:00 по Москве.
- Коммит от `GITHUB_TOKEN` не запускает другие конвейеры, иначе они бы
  вызывали себя бесконечно. Публикацию вызываю явно.
- Секреты не пишу ни в код, ни в `.env.example`, ни в историю: в журнале
  запуска они видны как `***`, а в репозитории лежат в настройках.

## Вывод

Доска стала многостраничной и перестала тащить данные через промежуточные
компоненты: один провайдер хранит список, а шапка и страницы читают его
сами. Параллельно появилось приложение, которое живёт без сервера: его
собирает и публикует конвейер, ночной скрипт проверяет сайты и пишет только
о реальных изменениях. Основной вывод модуля: то, что должно совпадать
везде, держу в одном месте — в контексте и в одном репозитории, а повторяющиеся
действия отдаю автоматизации.

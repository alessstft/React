## 20.11.2026 · поиск и флажок на странице «Сайты»

Инструмент: встроенный ИИ-агент в редакторе, режим Р2 (код пишет агент, я ставлю задачи и принимаю работу).
Правила проекта для агента: `AGENTS.md`.

### Попытка 1 — задача целиком
Задание: поиск по названию, флажок «Только неработающие», работа вместе, строка «Сайтов не найдено», с разделом «Готово, когда».
Агент прочитал `SitesPage.tsx` и тест, ответил «изменения не нужны, всё уже работает». `git status` пустой, новых тестов нет.
**Отклонено**: задача не выполнена, отчёт агента проверкой не является.

### Попытка 2 — задача по шагам
Шаг 1 (поиск). Агент изменил страницу. Отклонено после проверок:
- нет `import { useState } from 'react'` — `npx tsc -b`: TS2304, падают все тесты страницы;
- `useState` вызван после `if (loading) return` — `npm run lint -- --deny-warnings`: `react-hooks(rules-of-hooks)`;
- поле поиска оказалось под карточками, а требовалось над;
- лишний пробел в строке сводки, которую задача не трогала.
Шаг 2 (флажок) — код остался в чате, файл не изменён. Шаг 3 (тесты) — в тестах нет импорта `userEvent`, подпись «Поиск по сайту» не совпадает с полем, `userEvent.type` без `setup()` и без `await`.
**Отклонено**: 9 из 23 тестов падают.

### Возврат с замечаниями
Отправила список из пяти ошибок с готовыми правками. Агент читал файлы и запускал команды (в том числе несуществующий `npm run test:unit`), но ни одного файла не исправил. **Отклонено**: ждать дольше, чем исправить самой.

### Решение
Правки агента отменены. Поиск, флажок и тесты написаны вручную; из ответа агента взяты вычисление списка через `filter` и три сценария тестов.
Проверено: `npx tsc -b`, `npm run lint -- --deny-warnings`, `CI=true npm test` — 23 теста, `npm run build`. Страница пройдена с клавиатуры: Tab доходит до поля поиска и флажка, пробел отмечает флажок.

## 20.11.2026 · доступность
Проверки: Lighthouse (Accessibility, Desktop), дерево доступности в DevTools, проход клавишей Tab, линтер с `jsx-a11y`.

| Находка | Что сделала | Чем закреплено |
| --- | --- | --- |
| Контраст 3,44:1 у строки статуса, 4,36:1 у ссылок | заменила `#2e9d5b` → `#1e7a46`, `#2f6fde` → `#2563d0` | Lighthouse 100 на страницах «Сайты» и сайта |
| Карточка на `div` с `onClick` недоступна с клавиатуры | оставила `Link` | тесты `getByRole('link')`, плагин `jsx-a11y` |
| Название ссылки начиналось со статуса | поставила `<h2>` первым внутри карточки | тест `/^Справочник по React/` |
| Один заголовок вкладки на все страницы | `<title>` в каждой странице, шаблонная строка в `SitePage` | проверка `document.title` в `App.test.tsx` |
| Сообщения о загрузке и ошибке были немы для программы чтения | `role="status"` и `role="alert"`, `<caption>` у таблицы | тесты `getByRole('status')`, `findByRole('alert')` |

Правило `jsx-a11y/prefer-tag-over-role` выключено в `.oxlintrc.json`: `<output>` показывает результат вычисления, а надпись о загрузке сообщает о состоянии страницы.
В `deploy.yml` перед сборкой стоят `npm run lint -- --deny-warnings` и `npm test` — сайт с упавшим тестом или предупреждением не публикуется.

Токен бота и номер чата в вопросы не вставляла — они остаются в секретах репозитория.
